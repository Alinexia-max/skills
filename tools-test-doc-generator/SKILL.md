# 研发自测用例生成器

## 执行流程

### 1. 收集上下文

- 搜索 `design-doc/` 及项目根目录下的设计文档（关键词：设计/design/LLD/详细）
- 获取功能信息：用户提供 / 读取指定代码文件 / 搜索近期修改文件

### 2. 询问需求编号

**必须**询问：`请问本次用例对应的需求编号？（如无则留空）`。未提供时填"待补充"。

### 3. 生成用例

- **有设计文档**：以文档业务功能描述、流程为主要依据
- **无设计文档**：按代码功能流程推导测试场景
- **严格性**：用例内容必须基于代码和文档，不得虚构功能
- **业务导向**：步骤描述业务操作，预期描述业务结果，禁止出现接口路径/参数/响应字段
- **同操作合并**：同一操作的不同校验场景（如参数为空、记录不存在、权限不足等）合并为一条用例，步骤和预期结果用编号一一对应。避免同一操作拆出多条仅输入条件不同的用例

### 4. 输出文档

默认生成Excel，用户要求时生成Markdown。

**Excel**：
1. 将用例数据写入 `scripts/gen_test_excel.py` 的 `cases` 变量，设置 `OUTPUT_FILE`
2. 执行 `python scripts/gen_test_excel.py`
3. 文件名：`yyyyMMdd_test_{需求单号}_开发自测报告_通过.xlsx`，存于项目根目录，同日覆盖

**Markdown**：
1. 文件名：`研发自测文档_yyyyMMdd.md`，存于项目根目录，同日覆盖
2. 只含用例表格，不含标题/时间戳/说明等

## 用例表格

### 表头

| 用例编号 | 用例名称 | 前提条件 | 测试步骤 | 预期结果 | 备注 | 用例等级 | 用例类型 | 需求编号 | 功能模块 | 功能子模块 | 结果 |

### 字段规范

| 字段 | 规范 |
|------|------|
| 用例编号 | 从1递增 |
| 用例名称 | "动词+宾语"，如"创建用户成功" |
| 前提条件 | 业务前置条件，无则填"无" |
| 测试步骤 | 编号列出业务操作。合并用例时每个场景独立编号，如 `1. 正常填写信息点击保存 2. 用户名留空点击保存 3. 不传入记录编码` |
| 预期结果 | 与步骤编号一一对应的业务结果。合并用例时如 `1. 创建成功，列表显示新用户 2. 提示用户名不能为空 3. 提示记录编码不能为空` |
| 备注 | 补充说明，无则空 |
| 用例等级 | P0(冒烟/阻断) / P1(核心/正常) / P2(一般/辅助) / P3(边缘/低频) |
| 用例类型 | 功能测试 / 边界测试 / 异常测试 / 安全测试 |
| 需求编号 | 步骤2获取，未提供填"待补充" |
| 功能模块 | 一级模块名 |
| 功能子模块 | 二级模块名 |
| 结果 | 留空 |

## 核心约束

1. **禁止技术细节**：测试步骤和预期结果中严禁出现接口路径、请求参数、响应字段
2. **禁止虚构**：所有用例必须基于实际代码和设计文档
3. **覆盖度**：每个功能点覆盖正常+边界+异常场景，等级按重要性分配
4. **同操作合并**：同一操作的不同校验场景必须合并为一条用例，步骤与预期结果编号一一对应，避免拆出多条仅输入条件不同的用例
