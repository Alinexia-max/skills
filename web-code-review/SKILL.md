# Web 前端代码审查指南

## 审查范围

| 层次 | 审查对象 | 重点 |
|------|---------|------|
| Vue 组件 | `.vue` 文件 | 模板正确性、Script 规范、样式隔离 |
| TypeScript | `.ts` 文件 | 类型安全、接口定义、泛型使用 |
| API 层 | `src/api/**/*-api.ts` | 请求封装、错误处理、类型定义 |
| Store | `src/store/**/*.ts` | Pinia 规范、状态职责、方法命名 |
| 路由 | `src/router/**/*.ts` | 路由配置、权限控制、懒加载 |

## 检查维度

### 1. 语法与运行时错误（高优先级）

| 检查项 | 说明 |
|-------|------|
| 模板语法 | 指令拼写、表达式正确性、插值语法 |
| import 路径 | 使用 `@/` 别名而非相对路径乱跳；路径不存在或文件名大小写错误 |
| 未定义变量 | 模板中引用了未在 script 中定义的变量 |
| props 缺失 | 使用了组件但未传必填 prop |
| 方法调用 | 调用了不存在的方法 |
| 事件名 | emit 的事件名与父组件监听不一致 |
| v-for key | 循环渲染未绑定 key，或 key 使用了 index |
| 异步未处理 | await 未包裹在 try-catch 中 |

### 2. Vue 组件规范

| 检查项 | 要求 |
|-------|------|
| 文件名 | 大驼峰，如 `EmployeeList.vue` |
| Script | 使用 `<script setup lang="ts">`，禁止 Options API 混用 |
| 组件名 | 多词命名，避免与 HTML 原生标签冲突 |
| 样式 | 使用 `<style lang="less" scoped>`，禁止全局样式污染 |
| 模板简洁 | 模板中表达式不应过于复杂（超过 1 个三元运算应抽取为计算属性） |
| props 类型 | 所有 props 必须有类型定义，禁止无类型 props |
| emits 声明 | 所有 emit 事件必须在 defineEmits 中声明 |
| v-for + v-if | 禁止在同一元素上同时使用，应利用 template 或 computed 过滤 |
| 组件 import | 使用 `@/components/xxx` 路径而非相对路径 |

### 3. TypeScript 类型安全

| 检查项 | 要求 |
|-------|------|
| 避免 any | 不应出现不必要的 `any` 类型，至少用 `unknown` 替代 |
| 接口导出 | 公共类型定义应 export，且放在 `src/types/` 下 |
| 泛型 | 函数/组件应合理使用泛型而非 cast |
| 可选链 | 深层对象访问应使用 `?.` 而非 `&&` |
| 空值合并 | 默认值应使用 `??` 而非 `\|\|` |
| enum/const | 常量值应使用 `as const` 或 enum，不直接写字面量 |

### 4. Ant Design Vue 组件使用

| 检查项 | 要求 |
|-------|------|
| Table rowKey | `a-table` 必须绑定 rowKey，避免使用 index |
| Table 列定义 | 列配置应提取为数组/对象，不在模板中硬编码 |
| Form 校验 | `a-form` 的 `a-form-item` 应配置 rules 校验规则 |
| Modal 关闭 | `a-modal` 的 visible 双向绑定正确，关闭时重置表单 |
| Button 加载 | 异步操作的按钮应绑定 `loading` 状态防止重复提交 |
| 图标 | 使用 `@ant-design/icons-vue`，不使用 classname 方式 |
| Select 选项 | 选项数据应从 API 获取或定义为常量，不硬编码 |

### 5. API 层审查

| 检查项 | 要求 |
|-------|------|
| 命名导出 | 导出命名对象，如 `export const employeeApi = { ... }` |
| 统一请求 | 使用 `src/lib/axios.ts` 发送请求，不直接用 fetch/axios |
| 错误处理 | API 调用应有统一的错误处理，catch 中不吞异常 |
| 类型定义 | 请求参数和响应数据应有 TypeScript 类型/接口 |
| 路径规范 | 文件放在 `src/api/{模块}/{实体}-api.ts` |
| 分页参数 | 列表查询接口的请求参数应包含分页字段 |

### 6. Pinia Store 审查

| 检查项 | 要求 |
|-------|------|
| 风格 | 使用 Options API 风格（state/getters/actions） |
| 职责单一 | 一个 Store 只管一个领域，不把全局状态塞进一个 Store |
| state 类型 | state 属性必须有类型注解 |
| action 命名 | 使用动词开头：`fetchXxx`、`setXxx`、`clearXxx` |
| 跨 Store 引用 | 跨 Store 调用应有明确的依赖关系，避免循环引用 |

### 7. 性能问题

| 检查项 | 说明 |
|-------|------|
| 无意义的 watch | 监听了一个不变的值，或 watch 回调中无副作用 |
| 计算属性滥用 | 计算属性中做复杂运算或异步操作 |
| 大列表 | 超过 100 条数据的列表应启用虚拟滚动 |
| 图片懒加载 | 大量图片应使用懒加载 |
| 防抖节流 | 搜索输入、窗口 resize 等高频事件应做防抖/节流 |

### 8. 安全问题

| 检查项 | 说明 |
|-------|------|
| v-html | 禁止使用 `v-html` 渲染用户输入内容，存在 XSS 风险 |
| URL 拼接 | 禁止字符串拼接 URL，应使用 URL 参数对象 |
| 敏感信息 | 前端不应硬编码 token、secret 等敏感信息 |
| 用户输入 | 用户输入展示前应做转义处理 |

## 严重程度分级

| 级别 | 含义 | 处理策略 |
|------|------|---------|
| 高 | 运行时错误、类型安全隐患、XSS 风险 | 必须修复 |
| 中 | 规范违反、性能隐患 | 建议修复 |
| 低 | 代码风格、命名建议 | 可选修复 |
