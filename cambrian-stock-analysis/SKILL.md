# 寒武纪鳄鱼选股策略 - 股票分析 Skill

## 概述

⚠️ 本 skill 受口令保护。**仅当用户消息以"鳄鱼分析"开头时激活**，格式为 `鳄鱼分析 <股票名称或代码>`。其他任何形式的股票询问（如"分析一下XX"、"XX怎么样"）均不触发本 skill。

激活后，按照寒武纪选股策略的 10 因子评分体系对该股票进行深度分析，以固定格式输出分析报告，并**自动保存报告文件**。策略核心：央企/国企 + 业绩爆发 + 独一无二 + 低价低位 + 市值<200亿。

**报告保存路径（跨平台自适应）**：优先保存到**当前工作区根目录**，文件名 `{股票代码}-{股票简称}-鳄鱼分析.md`（例：`F:\研报\000928-中钢国际-鳄鱼分析.md`）。若同名的历史报告已存在，直接覆盖为最新版并在报告开头注明"第 N 次重评"及相对上一版的变化。原 Linux 路径 `/home/ubuntu/doc/{股票代码}.txt` 仅在 Linux 环境下作为兜底。

## 投资核心原则（分析时必须逐条对照）

以下 8 条是分析的基础逻辑，贯穿整个评分过程：

1. **股东背景**：央企或省国资委控股的国企（民企一票否决 — 见风控一）
2. **业绩爆发**：三年内扣非净利润增长 5-10 倍；或主要产品价格涨 2-3 倍；或单年业绩 3 倍以上增长
3. **独一无二**：产品或服务在国内不可替代，业绩不亏损
4. **主营集中**：主营业务占比集中，专注于一个领域
5. **模式简单**：业务模式简单，赚钱逻辑清晰可理解
6. **低价低位**：股价处于低位，历经三年以上盘整
7. **市值小**：总市值低于 200 亿人民币
8. **别无选择**：在行业中有独特优势，让资本没有其他选择，只能选它爆发

## 风控原则（一票否决项）

分析时必须优先检查以下 4 条一票否决项：

| 编号 | 风控条款             | 触发条件                      | 后果               |
|------|----------------------|-------------------------------|--------------------|
| 一   | 不买民企             | 实际控制人为自然人或民企      | 直接判定不买入     |
| 二   | 不买 ST 股           | 股票带有 ST 或 *ST 标识       | 直接判定不买入     |
| 三   | 不买业绩连降         | 近两年扣非净利润连续同比下降  | 直接判定不买入     |
**如果触发任一风控条款，立即输出不买入结论，无需继续评分。**

## 仓位与操作纪律（报告中必须包含）

- 账户最多同时持仓 **3 只股票**
- 主仓位不能低于总资金的 **70%**
- **原则上不使用融资**。唯一例外：千股跌停次日顺势下跌时，可使用 **30%** 融资，快速反弹后立即解除
- **中长线投资**，反对试探性交易和频繁交易
- 不在一个价位反复进出；没有把握就不买
- 不去寻找周期拐点，等周期真正走完拐点、进入上升阶段后再考虑
- 如果股价已经上涨，放弃；如果股价还没涨，进入

## 补充评估维度（可选参考，不计入 10 因子总分）

> 以下两个维度**不是 10 因子评分的一部分**，不计入 100 分总分。它们作为买入决策的**补充筛选与估值参考**，在报告末尾单独成节。当主评分临界或需交叉验证时尤其有用。

### 维度 A：五年复合增速筛选（增长底线校验）

**目的**：检验公司是否具备长期持续增长能力，而非仅靠单年爆发。

**数据**：取最近 5 个完整会计年度（T-4 至 T，即分析当年往前推 4 年）的年报数据（REPORT_DATE 含 `-12-31`）：
- 营业总收入：`TOTAL_OPERATE_INCOME`（或业绩报表 `REVENUE`）
- 归母净利润：`PARENT_NETPROFIT`（扣非不可用时替代）

**严格公式**：

复合年均增长率（CAGR，指数法）：

\[
CAGR_{rev}    = \left(\frac{REV_T}{REV_{T-4}}\right)^{\frac{1}{5}} - 1
\]

\[
CAGR_{profit} = \left(\frac{PROFIT_T}{PROFIT_{T-4}}\right)^{\frac{1}{5}} - 1
\]

> 说明：从 T-4 到 T 跨越 5 个会计年度区间，故开 5 次方（指数 `1/5`）。等价写法：总增长率开 5 次方根再减 1。

五年累计增长率（校验用）：

\[
TotalGrowth = \frac{VAL_T}{VAL_{T-4}} - 1
\]

**底线校验**：

| 指标 | 底线 | 判定 |
|------|------|------|
| 营收 CAGR | ≥ 8% | ✅ / ❌ |
| 利润 CAGR | ≥ 6% | ✅ / ❌ |

**结论规则**：两项均满足 → 增长维度通过；任一不满足 → 报告中标注"不满足五年复合增速底线"，作为"放弃/观望"的强化依据（此维度为补充参考，不直接触发一票否决，但会显著削弱投资价值）。

### 维度 B：FCF 倍数估值（严格公式）

**目的**：用自由现金流（而非会计利润）衡量估值贵贱，识别"便宜但基本面走弱"的陷阱。

**严格公式**：

\[
FCF = CFO - CAPEX
\]

\[
FCF\_Multiple = \frac{MarketCap}{FCF}
\]

其中：
- `MarketCap` = 当前总市值（统一换算为亿元口径）
- `CFO` = 年度**经营活动产生的现金流量净额**（经营现金流净额）
- `CAPEX` = 年度**资本性支出** = 购建固定资产、无形资产和其他长期资产支付的现金

**简化口径（轻资产 / 工程总包企业）**：CAPEX 占比极低（年 CAPEX 通常仅 1–2 亿，相对 CFO 可忽略），此时 `FCF ≈ CFO`，故：

\[
FCF\_Multiple \approx \frac{MarketCap}{CFO}
\]

**计算示例**（中钢国际 000928，2025 年报口径）：
- MarketCap = 70.87 亿元
- CFO = 12.92 亿元
- `FCF_Multiple ≈ 70.87 / 12.92 ≈ 5.5 倍`
- 若扣除估算 CAPEX（约 1–2 亿），FCF ≈ 11 亿 → 倍数 ≈ 6 倍

**估值判读（通用经验区间，工程 / 资源股参考）**：

| FCF 倍数 | 判读 |
|----------|------|
| < 8 倍   | 现金流估值偏便宜 |
| 8–15 倍  | 合理 |
| > 15 倍  | 偏贵 |

**注意事项**：
1. 工程总包类企业经营现金流季节性极强：Q1–Q3 通常为垫资净流出、Q4 集中回款。**必须用年报口径，不可看季度**。
2. CAPEX 字段在不同数据源命名不一（如 `CASH_PAY_ACQUI_FIX_INTAN` 并非通用字段）。若无法取得准确 CAPEX，明确标注"FCF≈CFO（轻资产近似）"并给出估算区间。
3. **FCF 倍数低（便宜）与营收 / 利润下滑并存时，属于"低估值但基本面走弱"组合——便宜 ≠ 有投资价值**，需结合维度 A 综合判断。

## 数据收集工具（本环境可用）

本环境没有 `web_search` 工具。数据收集统一使用以下四种方式，按优先级排列：

1. **`scripts/api-health-check.py --update`**（步骤 0，每次分析前首先运行）：自动检测所有端点可用性并更新标记
2. **`terminal` + `curl`**（首选，最快）：直接请求东方财富/新浪/腾讯的 JSON API
3. **`execute_code` + Python `urllib`**（解析复杂 JSON）：当 curl 一行不够用时
4. **`browser_navigate`**（最后手段，可能因 Chrome sandbox 限制不可用）：进入网页搜索

具体 API 端点参见 `references/api-endpoints.md`。

### 步骤 0：API 端点可用性自动检测（每次分析前强制执行）

**每次激活本 skill 后，第一件事就是运行端点检测脚本**，确保后续数据拉取使用最新可用的 API。

```bash
cd ~/.hermes/skills/research/cambrian-stock-analysis
python3 scripts/api-health-check.py --update -v
```

此行命令会：
1. **逐一测试** api-endpoints.md 中注册的所有 11 个端点（实时行情、基本面、财务数据、K线）
2. **自动更新** api-endpoints.md 中的 ✅/❌ 标记 — 失效的标 `❌`，恢复的标 `✅`
3. **输出 JSON** — 包含每个端点的 `available`/`unavailable` 状态和延迟

**检测后的自适应规则：**

| 端点                        | 默认可用 | 备用方案（不可用时）                                |
|-----------------------------|---------|---------------------------------------------------|
| 东方财富实时行情 (#1)        | ✅       | 降级到腾讯实时行情 (#2)                            |
| 腾讯实时行情 (#2)            | ✅       | 降级到东方财富 (#1)                                |
| 新浪实时行情 (#3)            | ❌       | 不可用时忽略，不影响分析                           |
| 公司概况 (#4)                | ✅       | 如不可用，实控人判断改用已知央企名单 + 百度百科     |
| 营收构成 (#5)                | ✅       | 如不可用，主营占比用财报备注文字推断               |
| 利润表 datacenter (#7)       | ✅       | 降级到新浪利润表 (#8)                              |
| 新浪利润表 (#8)              | ⚠       | 降级到 datacenter (#7)                             |
| 日K线 push2his (#9)          | ✅       | 无可靠备用；如不可用则跳过 K 线相关评分因子         |
| 月K线 klt=103 (#10)          | ❌       | 不可用时自动聚合日线 → 月线，不影响分析             |
| 周K线 klt=102 (#11)          | ⚠       | 不可用时用日线聚合代替                             |

**关键原则：**
- 至少有一个实时行情端点和利润表端点可用即可完成分析
- 如果多个关键端点同时不可用（如实时行情 + 利润表都挂了），在报告中明确标注"数据不完整"
- 不要因为某个端点挂了就放弃整个分析 — 用备用方案继续

> 脚本路径：`~/.hermes/skills/research/cambrian-stock-analysis/scripts/api-health-check.py`

### 步骤 1：风控审查（一票否决）

并行发起以下 API 请求收集风控数据：

- 实控人/企业性质：抓取 `emweb.securities.eastmoney.com` 公司概况接口（参见 api-endpoints.md #1），从 `jbzl` 字段判断实控人；同时用百度百科页面辅助确认。
- ST 标识：腾讯行情接口 `qt.gtimg.cn/q=szXXXXXX` 直接可见股票名称是否含 ST。
- 扣非净利润：东方财富利润表接口（参见 api-endpoints.md #3），取年报 `REPORT_DATE` 含 `-12-31` 的记录。
- 如扣非净利润字段不可用，用归母净利润（`PARENT_NETPROFIT`）代替，并在报告中注明。

确认以下三项：
- 是否为央企/省国资委控股？（民企直接否决）
- 是否为 ST 股？（ST 直接否决）
- 近两年扣非净利润是否连续同比下降？（连降直接否决）

**通过风控审查后才进入步骤 2**，否则直接输出不买入报告。

### 步骤 2：数据收集

并行获取以下数据（curl 可并发，python 脚本可聚合多接口）：

- 总市值/流通市值/股价：腾讯行情 API 或东方财富实时行情 API
- 年报归母净利润（及扣非，若可用）：东方财富利润表接口，所有 `-12-31` 记录
- 营收构成/主营占比：东方财富营收构成接口
- 月线 K 线（近 24-36 个月）：用日线数据 `klt=101` 聚合为月线（klt=103 月线接口不稳定）
- 成交量：从 K 线数据中提取

将搜索结果整理为结构化数据。

### 步骤 3：逐项评分

按照 10 因子评分体系，逐项打分：
- 完全符合 → 满分
- 部分符合 → 按比例给分
- 不符合 → 0 分

**每一项评分必须附上理由和数据支撑**，不得凭空打分。

### 步骤 4：输出格式报告

总分汇总后，按照下方报告模板输出。

### 步骤 5：自动保存报告（必须执行）

## 常见误区

1. **评分时凭感觉不附数据** — 每一项评分必须有具体的搜索数据支撑，不能 "看起来像是"。宁可搜索不完整，也不能编造数据。

2. **忽略风控审查顺序** — 风控审查必须先于评分。民企直接否决，不要因为其他条件好就给民企打分。

3. **评分宽严不一** — 因子#1（股东背景）：民企 0 分，地市国资委 5-7 分，省国资委 8-9 分，央企 10 分。建立统一尺度。

4. **忘记操作纪律** — 报告末尾必须包含仓位纪律和融资纪律，这是策略不可分割的一部分。

5. **用 PE/PB 等估值指标替代策略因子** — 主评分严格按 10 因子，不考察 PE/PB/ROE。但可考虑「补充评估维度」（五年复合增速 + FCF 倍数，见上文）作为可选参考；该维度**不计入总分**，仅用于交叉验证，不可替代主评分因子。

6. **不要硬编码"没有 web_search"** — 当前环境实际提供 `WebSearch` / `WebFetch`，可用于补充新闻、行业价格、政策等定性信息。但**行情与财务定量数据仍优先走 API**（更快、结构化、可复算），`WebSearch` 仅作交叉验证。数据收集方式按优先级：

7. **`DEDUCTED_PARENT_NETPROFIT` 字段不可用** — 东方财富 datacenter API 的多个 report 名称（RPT_F10_FINANCE_MAINFINADATA、RPT_LICO_FN_CPD、RPT_DMSK_FN_INCOME）均不包含扣非净利润字段。

   ✅ **已验证的还原方法（2026-09 实测）**：`RPT_LICO_FN_CPD` 提供 `BASIC_EPS` 与 `DEDUCT_BASIC_EPS`（扣非每股收益），按**当年加权股本**还原：

   ```
   隐含股本 = PARENT_NETPROFIT / BASIC_EPS
   扣非净利润 = DEDUCT_BASIC_EPS × 隐含股本
   ```

   ⚠️ **必须逐年计算隐含股本**，不可用当前总股本代替 —— 公司若有增发/转股，历史股本不同（例：中钢国际 2021 年 12.63 亿股 → 2025 年 14.35 亿股，误用当前股本会使 2021 年扣非虚高 14%）。实测该方法还原结果与财报披露值误差 <0.5%。一季度报告 `DEDUCT_BASIC_EPS` 常为 null，此时改用归母净利润同比并注明。

8. **K线首选腾讯接口，不要用 push2his** — 东方财富 `push2his.eastmoney.com` 日/周/月K线频繁返回 `Remote end closed connection`，且月线 `klt=103` 长期为空。改用腾讯K线（实测稳定）：

   ```
   GET https://web.ifzq.gtimg.cn/appstock/app/fqkline/get?param=sz000928,day,,,800,qfq
   → data.sz000928.qfqday : [[日期, 开, 收, 高, 低, 成交量(手)], ...]
   ```

   沪市前缀 `sh`，深市 `sz`；成交量单位与东方财富一致（手）。拉到日线后用 Python 按 `YYYY-MM` 聚合为月线（月末收盘、月均量、月内高低）。注意返回的部分 bar 可能有 7 个字段，解包时用切片取前 6 个。

9. **非资源股策略不匹配** — 10 因子体系专为资源股设计（依赖"产品价格大涨"和"净利润爆发"）。当用户要求分析非资源股（如工程、服务、科技类企业）时，因子 #3 和 #4 可能天然得 0 分。此时在报告的"评分解读"中注明这一局限，并建议用户考虑是否需要对非资源股扩展评分体系。
