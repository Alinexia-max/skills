# Java Code Review Skill

## 概述

该技能用于检查 Java 代码是否存在语法错误、编码格式不规范、性能需要优化等问题。
检测范围为 git 待提交代码（staged changes）或用户手动选中/输入的代码片段。
如果两项都没有，则主动询问用户检测范围。

**重点关注：**
- 语法错误（编译错误、空指针风险、资源未关闭等）
- 编码规范（命名、缩进、注释、代码结构等）
- 性能优化（循环低效、集合使用不当、字符串拼接、线程安全等）

**不检测：** JDK 版本兼容性

## 触发条件

- 用户要求"检查代码"、"代码审查"、"检测代码质量"、"代码review"、"检查Java代码"
- 用户要求"优化代码"、"性能分析"
- 用户提供 Java 代码片段要求检查

## 工作流程

### 第一步：确定检测范围

按照以下优先级确定检测范围：

1. **git staged 代码：** 执行 `git diff --cached` 命令获取待提交代码。如果项目不是 git 仓库或没有 staged 变更，跳过此步。
2. **用户选中代码：** 如果用户正在编辑器中选中了一段代码，直接使用该选中代码。
3. **询问用户：** 如果以上两项都不存在，询问用户希望检测什么范围：
   - a. 某个 Java 文件
   - b. 粘贴代码片段
   - c. 整个项目中的所有 Java 文件（可选，避免检测范围过大）

### 第二步：获取待检测代码

根据第一步确定的范围，获取代码内容：

- **git staged：** 使用 `git diff --cached -- '*.java'` 获取 Java 文件的变更内容。
- **选中代码/粘贴代码：** 直接使用用户提供的代码。
- **指定文件：** 使用 `read_file` 读取指定 Java 文件内容。

### 第三步：执行代码检查

对获取到的 Java 代码逐项检查，检查维度如下：

#### 1. 语法错误（优先级最高）
- 缺少分号、大括号不匹配、缺少 import
- 变量未初始化或未使用
- 方法缺少返回值
- 异常未处理或未声明 throws
- try-with-resources 未正确使用
- 潜在 NPE（空指针异常）
- 资源泄露（InputStream/Connection 未关闭）

#### 2. 编码规范
- 命名规范：类名大驼峰、方法/变量小驼峰、常量全大写
- 缩进风格不符合项目约定
- 过长的行（超过120字符）
- 过大的方法（超过50行应拆分）
- 过多的参数（超过4个应封装对象）
- 缺少必要注释（public API 缺少 Javadoc）
- Magic number（魔法数字未定义为常量）
- switch 缺少 default 分支
- equals/hashCode 未同时覆写
- 空 catch 块（吞没异常）

#### 3. 性能优化
- 循环中创建昂贵的对象（如 SimpleDateFormat）
- 字符串使用 `+` 连接而非 StringBuilder
- 集合使用时未指定初始容量
- 遍历 Map 时使用 keySet 再 get（应使用 entrySet）
- 在循环中调用数据库/网络/文件 IO
- 使用同步块但锁粒度过大
- 不必要的自动装箱/拆箱
- List.contains() 在循环中调用（应使用 Set）
- 大对象复制、不必要的深拷贝
- 递归未设置终止条件或深度过大

### 第四步：生成检测报告

将检查结果格式化为 Markdown 报告，报告结构如下：

```markdown
# Java 代码检测报告

**检测时间：** {当前时间}
**检测范围：** {git staged / 选中代码 / 指定文件}
**检测文件：** {文件名列表}

---

## 1. 语法错误（{数量}项）

| 问题描述 | 文件 | 行号 | 严重程度 |
|---------|------|------|---------|
| ... | ... | ... | ⚠️ 高 |

## 2. 编码规范（{数量}项）

| 问题描述 | 文件 | 行号 | 严重程度 |
|---------|------|------|---------|
| ... | ... | ... | 🔶 中 |

## 3. 性能优化（{数量}项）

| 问题描述 | 文件 | 行号 | 严重程度 |
|---------|------|------|---------|
| ... | ... | ... | ⚡ 中 |

---

**总结：** 共发现 {总数} 个问题（语法 {x} / 规范 {y} / 性能 {z}）
```

### 第五步：输出报告并下载

使用 `write_to_file` 将报告写入 md 文件，文件命名格式为 `java-code-review-report-{yyyyMMdd-HHmmss}.md`。
报告文件写入后告知用户文件路径。
